## Purpose
Cross-cutting map of the client: routing, bootstrap order, Redux/RTK Query shape, auth, PDF rendering + caching, and the shadcn/ui primitives every component builds on.

## Key Details

### App bootstrap order (`main.tsx`)
1. `getStoredClientId()` called at module scope — ensures `localStorage['dociq_client_id']` exists before any component or API call runs.
2. `<Provider store={store}>` ([[store]])
3. `<BrowserRouter>`
4. `<ThemeProvider defaultTheme="system" storageKey="dociq-theme">` ([[theme-provider]])
5. `<AuthProvider>` ([[AuthContext]])
6. `<App />` → renders `<Routes>` from `App.tsx`.

### Routing table (`App.tsx`, react-router-dom v7)

### Redux store shape ([[store]])
Only one slice: `state.api` — the entire RTK Query cache from [[baseApi]] (with [[chatApi]], [[commandApi]], [[documentApi]] endpoints injected into it). There is no hand-written application reducer; all local UI state is component-level `useState`.

### Auth flow
See [[AuthContext]] in full. Summary: an anonymous UUID (`localStorage['dociq_client_id']`, generated by `getStoredClientId()`) is the sole identity primitive. It is attached to every RTK Query request as the `x-client-id` header ([[baseApi]] `prepareHeaders`) and to the raw `EventSource` chat-stream URL as a `clientId` query param ([[useChat]]). **`@supabase/supabase-js` is installed and `lib/supabase.ts`/`lib/user.ts` exist but are dead code** — no Supabase session is ever created or read. Do not assume real user auth exists anywhere in this app.

### PDF rendering + IndexedDB caching
- Raw PDF bytes are **never served by the backend** — there is no download/view endpoint in [[API-Contract]].
- On successful upload ([[UploadModal]]), the raw `File` is written to IndexedDB via [[pdfStorage]] (`savePDF`), keyed by the server-assigned `documentId`.
- [[PDFViewer]] loads it back via `loadPDF(documentId)` on mount; if absent (e.g. opened on a different device/browser), it shows an "Attach PDF" empty state that lets the user manually re-supply the same file locally via `savePDF`.
- AI features (chat, summary/insights) are entirely independent of this cache — they work whether or not a local PDF blob exists, since the backend has its own copy of the extracted text/chunks/embeddings.

### shadcn/ui primitives (`client/src/components/ui/*`)
Unmodified vendored wrappers around Radix UI — not documented individually: `button`, `card`, `dialog`, `dropdown-menu`, `avatar`, `alert-dialog`, `badge`, `input`, `textarea`, `sonner` (toast). Treat these as a stable, un-customized base layer.
